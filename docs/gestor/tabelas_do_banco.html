Pontos de atenção

TB_TAXAS aparece com duas grafias

TB_TAXAS em beyond_cronograma.py e varcota.py, e TB_Taxas em acrual.py. Funciona hoje porque o collation do SQL Server é case-insensitive. Se produção vier com collation sensível a maiúsculas, acrual.py quebra.

O prefixo HOD_ sugere carga de terceiro

Pelo código não dá para saber se esses objetos são tabelas, views ou sinônimos apontando para outra base. Se forem views ou sinônimos, a migração precisa levar a origem também — senão o objeto existe e vem vazio. Não pude confirmar porque estou sem acesso ao banco; a consulta que resolve é no sys.objects filtrando por esses nomes.
